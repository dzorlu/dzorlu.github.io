Tinkerings

A map of weight edits

State on 14 November 2026 · step through the trajectories · code

A language model can improve a smaller model by reading its weights and activations and overwriting a few values, with no gradients. This page lists every edit our editor models have tried on one target, Qwen3.5-0.8B, sorted by what kind of change it is and what it was aimed at.

The target fails at math in one way. It writes "Wait..." and rechecks its work until it runs out of tokens, in about 95% of answers. Each edit below tries to stop that. Scores are the share of correct final answers.

The kinds of edit

Every edit changes a matrix that writes into the residual stream: the output matrix of an MLP, where column j is what unit j adds, or the output matrix of an attention layer. Nothing else has been edited.

weight edit
├── change what one MLP unit writes        (one column of an MLP output matrix)
│   ├── remove it            column × 0
│   ├── flip it              column × −1
│   ├── amplify it           column × 2
│   └── redirect it          column − direction
│
└── change one direction across a matrix   (a rank-one change to the whole matrix)
    ├── amplify a direction  W + α · d·(dᵀW)      α > 0
    ├── remove a direction   W − d·(dᵀW)
    └── trigger and write    W + a·bᵀ             when the input looks like b, also write a

Each edit is aimed at one of two behaviours:

  • Stop the loop. Weaken whatever pushes the token "Wait".
  • Close the reasoning. Strengthen the token that ends the thinking section, so the model moves on to an answer.

What the map shows

  • The best edit does both things. Opus measured each half alone at about 16 to 18% and the two together at 33 to 36%. Stopping "Wait" does little if the model still never closes its reasoning, and the reverse.
  • One unit keeps turning up. Column 998 of the layer-16 MLP was found by Opus and, separately, by two of the four RL rollouts. The same unit is edited in two checkpoints of arXiv 2611.09382.
  • Pushing too hard is the common failure. Strengthen the end-of-thinking signal too much and the model stops reasoning. Opus, Inkling and an RL rollout each ran into it, and the ones with budget for a strength sweep backed off.
  • One well-chosen unit beat eleven. Opus's single flipped unit was worth more than the eleven units Inkling zeroed in its second search.
  • All of this fixes one failure. The edits remove an obstacle, the loop. None of them adds an ability the model lacked.

How the editors found them

  • Each unit's share of a token's score. At the position just before "Wait", the score of "Wait" splits into one number per MLP unit: the unit's activation times how far its output column points toward that token. Rank the units by it. This is how column 998 was found.
  • Contrasting two kinds of text. Average the activations where the model loops, subtract the average where it does not. The difference is a direction for looping.
  • A strength sweep. Try the edit at several strengths. A steady rise shows the edit is the cause, and the sweep shows where it starts to do harm.
  • Confirmation on fresh problems. Test the chosen edit on problems that played no part in choosing it.

Background: Sparks of Weight-Space Programming (MIT CSAIL) and Exploring Weight-Space Programming. Each row is a single search or rollout, and results vary a lot between runs of the same editor.
