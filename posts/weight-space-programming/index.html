Weight-space programming

State on 14 November 2026, 19:10 · live RL run · step through the trajectories · changelog · code

Can a model improve another model by editing its weights directly, with no gradients [1] [2]? We set this up as a teacher and a student.

  • Student: Qwen3.5-0.8B. It solves math problems from MATH and GSM8K. This is the inner loop.
  • Teacher: Claude Opus 5.5 or Inkling 2 Small. It works in many steps. It runs the student, reads its answers and activations, writes an edit to its weights in code, and tests the edit on problems. At the end it submits its best edit.
  • Training the teacher: we train Inkling 2 Small with RL. The reward is how much its submitted edit improves the student's accuracy on problems it never saw.

The student fails at math mostly because it does not stop reasoning. It writes "Wait..." and rechecks its work until it runs out of tokens. This happens in about 95% of answers. Every edit below tries to fix this, in one of two ways, or both:

  • Stop the loop. Lower the score of "Wait", so the model stops re-checking.
  • Close the reasoning. Raise the score of "</think>", so the model ends its thinking and gives an answer.

A score is the share of correct final answers. Edits are scored on three sets of problems:

  • Train: MATH and GSM8K training problems, used during the search. Some are set aside as validation, to check the final edit.
  • Test: MATH-500, scored once on the submitted edit.
  • Reward: 128 other MATH training problems, used to score each RL rollout. The teacher never sees them.

The localization and edit patterns the teacher models deploy resemble mechanistic interpretability methods, which I illustrate below. We now list these methods in the teacher's prompt. But the teachers used them before we did.

The page has three parts:

  • How to diagnose: how the teacher finds what to change.
  • How to update: how it changes the weights.
  • Every edit tried so far, and what the edits show.

How to diagnose

A diagnosis finds the units that make the model write the wrong next token. Here that token is "Wait". The teachers used three methods from the interpretability literature:

  1. Direct logit attribution: which unit writes "Wait"?
  2. Difference of means: which unit fires differently just before "Wait"?
  3. Token directions: no measurement. Use the token's own direction.

Method 1 is built up below on a one-layer network.

1. Direct logit attribution [3] [4]

A small network

Start with a toy network. It has the same parts as the student, only smaller.

Because h is the residual plus what the MLP added, the "Wait" logit splits the same way, with u = U[:, Wait]:

$$\text{logit}_{\text{Wait}} = h \cdot u = (h_0 + xW)\cdot u = \underbrace{h_0 \cdot u}_{\text{residual: }0.5} \;+\; \underbrace{\sum_j x_j \,(W_j \cdot u)}_{\text{MLP, one term per row of }W:\ 2.5} = 3$$

Figure 2 opens up the MLP part. It has one term per unit.

Where a logit comes from

Across positions and layers

Figure 2 shows one position: one token whose next token is "Wait". A looping answer writes "Wait" many times. Let P be all those positions. Unit j is one MLP neuron: entry j of x, row j of W. For each layer L and unit j, add the unit's contribution over P:

$$C_L[j] = \sum_{p \in P} x_L[p, j]\,\bigl(W_L[j] \cdot u\bigr) \,/\, \text{rms}(h[p])$$
  • rms(h[p]) is the final norm. It scales every term at one position by the same number.
  • C has one number per unit per layer.
  • The unit with the largest C is the candidate to edit.
  • C counts only what a unit writes straight into the final vector. So we confirm a candidate by editing it and generating answers.

Each teacher ran this search in a different way:

  • Opus: layers 12 to 23. It summed the positions before "Wait" in 2 answers.
  • Inkling: layers 22 and 23 only. It summed every position of 1 answer.

2. Difference of means [6] [7]

Method 1 asks which unit writes "Wait". Method 2 asks which unit fires differently just before "Wait". It needs only the activations x. It compares two sets of positions:

  • P: positions whose next token is "Wait", as in method 1.
  • Q: positions to compare against. These are either the other positions of the same answer, or positions in answers that finished cleanly.

Example: unit 2 fires 3 and 2 at the positions in P, and 0 and 1 at those in Q. Its means are 2.5 and 0.5, so the difference is 2. It fires mostly before "Wait".

$$d[j] = \text{mean}_{p \in P}\, x[p, j] \;-\; \text{mean}_{q \in Q}\, x[q, j]$$

The units with the largest d are the candidates. On the residual stream h, the same difference gives a direction instead of a unit. That direction can be removed from the output matrices [6].

3. Token directions

This method skips the measurement. Each token has a column in U. That column is a direction in the residual stream. We can remove it from the output matrices of every layer, or add it. Removing it from every layer is called directional ablation [6].

Inkling used this method in its first search. It saw that layers 15 to 21 push "</think>" down. So it added the "</think>" direction to the MLPs of layers 20 to 23. Test accuracy rose from 6.6% to 20.2%.

How to update

A diagnosis gives a unit or a direction. The teacher then changes the weights there. It only edits output matrices: the matrix W from How to diagnose, which writes an MLP's result back into the residual stream, and the same matrix in attention layers. No other weights are changed.

There are two kinds of edit:

  • Change a few units. Each unit has its own slice of the matrix: what it writes. Changing it changes only that unit.
  • Add a rank-one term a·bᵀ [5]. This touches every unit. It changes what the whole matrix writes along one direction.

Opus's and Inkling's largest gains came from rank-one terms.

The figures in this section draw W as it is stored in the model file, [1024 × 3584]. Unit j is column j here. In How to diagnose we used the transpose, so unit j was row j. It is the same matrix.

The figure below shows a small W before and after an edit. Rows are residual dimensions. Columns are MLP units. positive weight, negative weight, zero. A stronger colour means a larger weight. marks the cells the edit changes. The rest are faded.

Kinds 1 to 4 change one column. The other columns stay the same. Kinds 5 to 7 add a rank-one term a·bᵀ, so they can change every cell. Cell (i, j) changes by a[i] × b[j].

What the edits show

  • The teachers found only two error modes. The model re-checks its work in a loop ("Wait"), and it never ends its reasoning ("</think>"). Both end the same way: the answer is cut off at the token limit.
  • The best edit does both. Opus tested each half alone and both together. Together was about twice as good as either half.
  • One unit keeps turning up. Unit 998 in the layer-16 MLP. Opus found it, and so did several RL rollouts. Two checkpoints in arXiv 2611.09382 also edit it.
  • Pushing too hard is the common failure. If the end-of-thinking score rises too much, the model stops reasoning. Opus, Inkling and one RL rollout all hit this. The teachers that tested several strengths backed off.
  • The largest gains edit many layers. In hero3 step 1, the two best rollouts removed the "Wait" direction from every output matrix and added the end-of-thinking direction. Edits to a few units earned less.
  • No edit tried anything else, such as arithmetic mistakes or wrong answers in finished solutions. A likely reason: the teacher starts with a summary of the student's answers, and that summary points straight at "Wait".
